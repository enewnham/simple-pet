# MCP tools and evidence

The MCP server answers questions about captured work. It reads local storage and
a private runtime snapshot published by the daemon. Workstream write tools append
caller marks to a separate local store. They never change captured evidence, send
commands to a harness, or change a repository. HTTP and stdio expose the same tools.

## Find a thread

Call `workstreams()` for recent checkout and session threads. Each entry has a
stable opaque `id`, checkout, sessions, last agent activity, an extractive one-line
summary, and branch, PR, and ticket claims with their source passages. Pass that ID
to `workstream(id)` for detail.

Reports group by captured checkout. Reports without a checkout group by harness
session identity. No directory root or workbench layout is assumed. A branch
observation joins a checkout when its repository and branch identify one checkout.
Ambiguous branch observations remain separate. Explicit captured PR references can
join PR observations to a thread when the association identifies one thread.

The list includes threads with captured agent activity in the last seven days.
Observation-only threads qualify with a recent available checkout or open PR.
Repository refreshes do not extend a report thread's agent activity. This is a
recent-work list, not proof that every listed session is running. Use `sessions`
for process-verified sessions. A known thread ID remains readable after it leaves
the recent-work list.

`workstream(id)` returns the effective goal as `goal`, the first retained intent as `captured_goal`, the first intent for
each contributing session as `session_goals`, recent turns, decision/correction
candidates, question candidates, and current retained repository observations.
Checkout reuse can place several session goals in one thread. The first retained
intent may predate the latest task. Unknown goals remain null.

Branch, PR, and ticket claims retain their individual sources. A reported branch
is the branch captured with that report. Repository state remains a separate
observation with its collection time. A later checkout observation never rewrites
what an earlier report said.

## Mark a workstream

`mark_workstream(id, author, reason, ...)` appends caller judgments. Supply a caller
label in `author` and a nonblank explanation in `reason`. Optional fields are:

| Field | Values |
| --- | --- |
| `status` | `active`, `paused`, `blocked`, `waiting-review`, `done`, `abandoned` |
| `priority` | `focus`, `normal`, `background` |
| `tags` | A replacement list of free-form tags |
| `note` | A note of up to 2,048 characters |
| `goal` | A nonblank one-line goal, up to 240 characters |
| `title` | A nonblank one-line title, up to 160 characters |
| `blocked_on` | A description of the blocker, up to 512 characters |
| `snooze_until` | A Unix timestamp |

Omitted or null fields stay unchanged. Empty tags clear the tag list. To clear
other fields, call `unmark_workstream(id, author, reason, fields)`. Omitting `fields`
clears all effective marks. Clearing is another history event, never a deletion.
`workstream_mark_history(id, limit, before)` reads events newest first. Follow
`next_before` for older events. Each event records author, authenticated principal,
timestamp, reason, operation, and changed fields. Field-level provenance retains
who last changed that field, even when another caller changes a different field.

Titles use a source-backed extractive label generated by Simple Pet. Reads return
`title`, `title_provenance`, and `generated_title`. A caller title overrides the
effective title. Clearing it restores the generated title and Simple Pet
attribution. A goal mark changes `goal` and `effective_goal`; `captured_goal` and
`session_goals` preserve the original intents.

`workstreams`, `current_work_context`, and `attention` exclude done, abandoned,
and future-snoozed threads. Blocked or focus threads rank ahead of normal threads.
Paused or background threads rank lower. Explicit active, blocked, waiting-review,
or focus marks can keep an older captured thread in `workstreams`. A blocked mark
also creates an attention item. Direct `workstream(id)`, source reads, search, and
evidence change queries remain available for hidden threads.

Marks have `basis: marked`, separately from `reported` and `observed` evidence.
They live in `<memory filename>.marks.sqlite3`, with mode `0600` and append-only
history. HTTP writes use the existing bearer credential. Both write tools advertise
`read_only_hint: false`; other tools remain read-only. `author` is a caller-supplied
label. The shared bearer principal proves possession of the shared credential,
not an individual identity. Stdio calls record a local principal. No token is
stored in mark history. Any authorized caller can change another caller's marks,
and history retains both actions.

## Catch up

Call `since(ts)` with a Unix timestamp. It returns retained sources changed strictly
after that time, grouped into the same threads. Reports use ingestion time when
available. Repository observations use collection time. Grouping uses all retained
context, including reports older than `ts`, while returned sources respect `ts`.

The result is a bounded snapshot. Repeated repository refreshes can appear as
changes. Overwritten observations and deletions are unavailable. Use source IDs
and revisions to recognize repeated evidence. This tool does not provide a durable
change-log cursor.

## See live sessions and attention

`sessions()` returns verified harness sessions with `working`, `idle`, or
`waiting_on_permission` state, joined to captured reports and repository context.
Each record includes a workstream ID, last activity, process-check time, waiting
kind/prompt, and `activity_uncertain`. State reflects the daemon's accepted hooks.
An uncertain activity flag qualifies that state.

The daemon publishes `<memory filename>.sessions.json` beside the configured
memory database every five seconds. The file is atomically replaced with mode
`0600`. Both the snapshot and each process observation expire after 15 seconds.
Sessions without verified live processes are excluded. Suspension publishes an
empty session list. Shutdown removes the publishing daemon's snapshot.

`live_available: false` means the snapshot is missing, stale, unreadable, or belongs
to another pet. An empty list in that case cannot establish that no harness is
running. Runtime source IDs begin with `session:` and remain readable through
`read_passage` while the matching session has fresh evidence. Their revisions can
change on each heartbeat. Runtime snapshots are not retained in `since`.

`attention()` returns these evidence-backed items:

| Kind | Meaning |
| --- | --- |
| `permission_pending` | A fresh live session is waiting for permission |
| `failed_turn` | The latest retained report for a session reports a failed turn |
| `unanswered_question` | A live idle session is waiting for an answer, or its latest assistant report contains a question |
| `stalled_pr` | An observed open PR's thread has no captured agent activity for at least 24 hours |

Failure, lexical question, and stalled PR items have `candidate: true`. A new
intent or later report supersedes a failure or lexical question. An explicit
runtime question wait has `candidate: false`. A stalled candidate does not establish
that the PR lacks GitHub activity. Verify live state before treating it as blocked.
Missing live evidence does not suppress retained failure and stalled PR candidates.

## Inspect decisions and original text

`decisions(query)` returns exact report excerpts containing explicit decision or
correction wording, such as “decided,” “we chose,” or “correction:”. Query words
must all occur in the excerpt, ignoring case. An empty query returns recent
candidates. Each result includes its thread, captured location/context, observation
time, and original source passage. These lexical candidates can include quoted,
negated, or superseded decisions. They are not a complete semantic decision log.

`workstream` uses the same decision extraction. Its open questions are lines with
question marks from the latest assistant report in each session. A later user
intent removes that session's earlier question candidates.

Use `context_search(query)` for broad report word searches and literal repository
observation searches. Use `read_passage(source_id, offset, length)` for original
text. Follow `next_offset` to continue a longer passage.

Identical progress and execution reports from one agent observation use one result
slot. The execution report supplies the result ID and provenance. Other stored
report IDs remain readable. Distinct turns and sessions keep separate results.

## Provenance and limits

Every summary, claim, excerpt, turn, and attention item carries supporting source
passages. Passages retain `basis: reported` or `basis: observed`, source timestamps,
revision, and a readable source ID. Report passages include observed, capture, and
ingestion times. Repository passages include `checked_at`. Runtime passages include
`observed_at` and the daemon runtime basis. Envelope `checked_at` records query time,
not a fresh collection of repository state.

Tools accept `limit` from 1 to 50. Thread lists and per-thread detail lists are
bounded separately. Inspect envelope `truncated` and per-thread truncation fields,
including `sessions_truncated` and `metadata_truncated`. Passage text defaults to
1,200 characters. `read_passage` accepts up to 12,000 characters at a time.

`current_work_context` retains the flat source selection API with checkout balance,
seven-day freshness ranking, and closed PR observations ranked last.
`relevant_changes(after)` retains the flat change API. Prefer `workstreams` and
`since` when exploring threads.

Restart the daemon with `make restart-agent` to publish live session snapshots.
Restart the HTTP MCP agent with `make restart-mcp-agent` to load tool changes.
Reconnect a stdio client to launch a fresh MCP process. The tunnel needs no restart.
No storage schema change is required.
